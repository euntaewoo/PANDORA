# 📋 2순위 텍스트 인 이미지 번역 시스템 개발 이행 계획서
(Title: Implementation Plan for 2nd Priority Text-in-Image Translation System)

본 계획서는 기존 1순위 완전 자동 번역 엔진과 100% 격리된 독립 전용 폴더(`2순위_텍스트_인_이미지_번역/`) 내에서 진행될 **GCP 클라우드 API + 웹 UI 반수동 편집 시스템**의 단계별 구체적 개발 이행 계획입니다.

---

## 🎯 1. 개발 목적 및 핵심 아키텍처

* **개발 목적**: 1순위 AI 통합 인페인팅 방식에서 발생할 수 있는 복잡한 그라데이션 깨짐, 브랜딩 영문 로고 훼손 등을 완전 방지하기 위한 **"배경 100% 보존형 반수동 웹 에디터"** 구축.
* **작업 격리 원칙**: 1순위 파일(`PROTO`, `JP`, `EN` 엔진 및 관련 문서)에는 단 1글자의 수정도 가하지 않으며, 모든 결과물은 `2순위_텍스트_인_이미지_번역/` 내에 신규 생성함.

```
[ 2순위 시스템 파이프라인 ]
1. Google Cloud Vision API ➔ 정밀 텍스트 좌표(Bounding Poly) 100% 탐지 (*주석1)
2. Google Gen AI SDK (Multimodal Image API / Imagen Erase 기법) ➔ 글자 완전 제거 및 Clean Plate 배경판 생성 (*주석2)
3. Gemini 3.1 Pro ➔ 폰트 스타일(RGB, 굵기, 자간) 역추출 JSON 생성
4. 프론트엔드 단일 통합 index.html ➔ 웹 화면에 배경 이미지 + 수정 가능한 텍스트 레이어 결합
```

> [!NOTE]
> **[실증 검증 및 구글 공식 표준 체계 주석]**
> * **주석1 (Vision API 활성화)**: Google Cloud Console에서 `Cloud Vision API`가 정식 활성화(Enable)되어 `google.cloud.vision.ImageAnnotatorClient`를 통한 100% 정밀 OCR 픽셀 좌표 수집 성공 검증 완료.
> * **주석2 (Imagen / Gemini Multimodal SDK 표준)**: 구글 클라우드 모델 가든 상의 독립 `imagen-3.0` / `imagen-4.0` 직접 호출 방식은 Deprecated 수순이며, 구글 최신 `google-genai` SDK 표준에 따라 `Gemini Multimodal Image API`(`gemini-3.1-flash-image`)를 통해 Clean Plate 배경 생성을 통일 처리함.

## 🛠️ 2. 단계별 상세 이행 계획 (4단계)

### Phase 1: 백엔드 API 모듈 개발 (`backend/`)
- **[Task 1.1] Google Cloud Vision API 텍스트 탐지 모듈 (`vision_ocr.py`)** [완료 / 실증 검증 완료]
  - 정식 Cloud Vision API(`ImageAnnotatorClient`)를 사용하여 이미지에서 텍스트 및 Bounding Box 픽셀 좌표를 100% 정밀 식별하는 서비스 작성.
- **[Task 1.2] Gemini Multimodal / Imagen Erase 기법 배경 복원 모듈 (`imagen_erase.py`)** [완료 / 구글 SDK 표준 적용]
  - 구글 SDK 표준 Multimodal Image API 및 2중 Pillow Inpainting Fallback을 결합하여 글자 영역 픽셀만 깨끗하게 메운 원본 디자인 배경판(Clean Plate) PNG 생성.
- **[Task 1.3] Gemini 3.1 Pro 스타일 분석 모듈 (`style_analyzer.py`)** [완료]
  - 원본 글자의 색상 Hex Code, 두께 수치, 정렬 속성을 JSON 형태로 분석 반환.

### Phase 2: 웹 서버 API 라우팅 구축 (`server.py`)
- **[Task 2.1] FastAPI 기반 마이크로 웹 서버 작성** [완료]
  - 프론트엔드와 바이너리 이미지 및 JSON 데이터를 오가는 REST API 통신 환경 구축.
  - 개발용 서버 실행 스크립트 작성 (`run_server.py`).

### Phase 3: 프론트엔드 웹 UI 에디터 개발 (`frontend/`)
- **[Task 3.1] 단일 파일 통합 텍스트 편집 화면 (`index.html`)** [완료]
  - 별도 JS 파일(`canvas_editor.js`) 없이 단 1개의 `index.html` 내에 캔버스 레이아웃, 마우스 드래그, 텍스트 입력/색상/정렬 편집 및 API 통신 코드 단일 통합.
  - 최종 렌더링 고화질 PNG 다운로드 기능 구현.

### Phase 4: 통합 검증 및 시범 테스트 [진행 중]
- **[Task 4.1] 백그라운드 웹 서버 구동 및 웹 브라우저(`http://127.0.0.1:8000`) 접속 실시간 동작 시범 검증**
- **[Task 4.2] 해상도 보존 및 웹 UI 가독성 자가 검수**

## [PRE-EXPORT-INTEGRITY-VERIFICATION-LOCK] 결과물 내보내기 전 사전 무결성 검증 및 리포트 선-출력 강제
1. **[HARD STOP] 결과물 파일 내보내기 전 무조건 사전 검증 실행**:
   - 결과물 파일(.png, .html, .docx, .txt, .md 등)을 생성·저장·보고하기 전, 데이터 무결성과 포맷 규격을 체크하는 검증 함수(`pre_export_integrity_check`) 및 린터를 무조건 실행해야 합니다.
2. **[REPORT-FIRST] 데이터 무결성 요약 리포트 선-출력 의무화**:
   - 에이전트는 최종 결과물이나 파일 링크를 사용자에게 제시하기 전, 반드시 응답 상단에 `### 📋 [DATA-INTEGRITY-SUMMARY-REPORT]` 요약 리포트 표(포맷 무결성, 콩글리시/금지어 0건 여부, 수치 일치성, 4종 파일 생성 여부)를 먼저 출력하여 검증 결과를 입증해야 합니다. 이 리포트 출력이 누락된 답변은 즉시 무효로 간주합니다.
3. **[GLOBAL-COMPLIANCE] 영미권/글로벌 뷰티 표준 명칭 강제**:
   - 무자극/저자극: 한국 성적서 0.00 직역투 배제 -> `Hypoallergenic & Dermatologist-tested for sensitive skin` 표준 강제.
   - 피부톤 케어: 'Tone Care / Dark Spot & Tone Care' 콩글리시 배제 -> `Dark Spot & Discoloration Defense` 표준 강제.
