🔄 2. 백엔드 워크플로우 (서버 내부 연산 단계)
사용자가 버튼을 누르는 순간, 서버 엔진 내부에서는 시스템 레이어가 분리되며 아래의 순서로 연산이 진행됩니다.
1단계: 텍스트 및 외곽선 탐지 (Detection & Masking)
적용 기술: PaddleOCR + SAM
처리 내용: 이미지 스캔 후 글자 위치를 파악하고, 글자 형태 그대로의 픽셀 마스크(Mask)를 생성합니다. 이때 복잡한 배경과의 경계선을 수학적으로 분리합니다.
2단계: 이미지 레이어 독립 (Layer Separation)
적용 기술: 그래픽 가상화 레이어 엔진
처리 내용: 원본 이미지에서 1단계의 글자 픽셀만 칼로 오려내듯 상위 스택(정형 데이터 레이어)으로 들어 올립니다.
3단계: 하부 원본 배경 복원 (LaMa Inpainting)
적용 기술: LaMa 코어 알고리즘
처리 내용: 글자가 빠져나가 구멍 뚫린 하부 배경 레이어에 인페인팅을 가동합니다. 주변 픽셀의 그라데이션, 패턴, 질감 데이터의 연속성을 계산하여 글자가 원래 없었던 것처럼 깨끗한 통배경(Clean Plate)으로 메워 독립된 이미지 파일로 보존합니다.
4단계: 텍스트 객체 변환 (Text & Font Vectorization)
적용 기술: 서체 매칭 엔진 + 가변 텍스트 박스
처리 내용: 2단계에서 떼어낸 픽셀 글자를 키보드로 수정할 수 있는 실제 문자(String) 데이터로 변환하고, 원본과 유사한 다국어 폰트 스타일을 매칭해 상위 레이어에 배치합니다.
✍️ 3. 셀러가 수행하는 '반수동 작업' 실무 순서
백엔드 기술이 '깨끗한 배경'과 '수정 가능한 글자'를 완벽히 쪼개놓으면, 셀러는 아래의 순서대로 마무리를 지어 최종 결과물을 완성합니다.

[1. 이미지 업로드 및 추출 버튼 클릭] -> AI가 배경/글자 레이어 분리 가동                 │                 ▼[2. 원본 한국어 글자 레이어 삭제] -> Delete 키로 배경에서 글자 흔적 완전히 제거                 │                 ▼[3. 현지어 번역문 복사 및 붙여넣기] -> 챗GPT 등으로 검수된 정확한 텍스트 입력                 │                 ▼[4. 레이아웃 및 가독성 수동 정렬] -> 폰트 크기 조절, 정렬 확인, 필요시 반투명 박스 배치                 │                 ▼[5. 최종 상세페이지 이미지 다운로드] -> 쇼피 업로드용 고화질 파일 추출
이미지 준비 및 AI 구동: 캔바 매직 스튜디오 등 편집 창에 상세페이지를 올리고 텍스트 추출을 실행합니다. (AI의 자동 영역 종료)
원본 글자 일괄 삭제: 앞으로 툭 튀어나와 분리된 한국어 텍스트 박스들을 선택해 키보드의 [Delete] 키를 눌러 삭제합니다. (화면에는 글자가 완벽히 지워진 원본 디자인 배경만 남게 됩니다.)
검수된 번역문 삽입: 챗GPT나 파파고로 미리 번역·검수해 둔 매끄러운 현지어(영어, 태국어 등) 문장을 [Ctrl+C ➡️ Ctrl+V] 하여 배경 위에 새 텍스트로 얹습니다.
디자인 정렬 및 가독성 방어 (핵심 수작업): 한국어보다 길어진 현지어 문장 때문에 줄바꿈이 일어났다면 마우스로 텍스트 박스 끝을 늘려 잡거나 폰트 크기를 조절합니다. 만약 복잡한 배경 탓에 인페인팅 흔적이 흐릿하게 남았다면 그 위에 반투명 사각형 도형을 깔아 글씨를 더 선명하게 돋보이게 만듭니다.
출고 및 저장: 정렬이 완료되면 고화질 이미지(PNG/JPEG)로 내보내기 하여 쇼피 글로벌 셀러 센터에 등록합니다.
🔎 요약판단
이 워크플로우는 "가장 성가시고 찌꺼기가 많이 남는 배경 청소(인페인팅)는 AI에 전적으로 맡기고, 디자인의 디테일과 줄바꿈 정렬, 번역의 정확성은 인간 셀러가 통제"하는 구조입니다.
자동 번역기의 고질병인 '디자인 무너짐'과 '어색한 직역 오류'를 원천 차단할 수 있기 때문에, 시간이 조금 더 걸리더라도 해외 마켓플레이스에서 구매 전환율을 극대화해야 하는 핵심 유료 광고 상품 및 주력 효자 상품 상세페이지 제작 시 가장 완벽한 해답이 됩니다.
이 반수동 프로세스를 적용할 첫 번째 상세페이지의 글자 분량(텍스트가 많은 편인지, 간결한 타이틀 위주인지)을 말씀해 주시면, 4단계 수작업 정렬 시간을 절반으로 줄일 수 있는 세부 레이아웃 세팅 팁을 추가로 제안해 드릴게요.

✍️ 4.캔바 텍스트 인 이미지 번역 시 가장 정교한 품질을 내는 
"인페인팅 대신 '텍스트 추출 후 배경 보존'" 방식

캔바 UI를 사용하는 일반 유저(Frontend)부터 API 통신망, 그리고 파이썬 기반의 백엔드(Backend/서버) 내부 기술 스택까지 전체 아키텍처를 명확하게 매칭하여 정리해 드립니다.

🔄 2). 워크플로우 단계별 기술 적용 및 작동 매커니즘
유저가 브라우저에서 버튼을 누르는 순간부터 서버 내부 연산을 거쳐 최종 편집 화면이 완성되기까지의 5단계 정밀 워크플로우입니다.
[유저 단: 이미지 업로드] ──(API: 이미지 송신)──> [서버 단: 파이썬 AI 가동]
                                                  │
                                                  ▼
                                      1단계: OCR 텍스트 위치 탐지
                                      2단계: SAM 정밀 글자 마스킹
                                      3단계: LaMa 하부 배경 인페인팅 복원
                                      4단계: 폰트 스타일 매칭 및 벡터화
                                                  │
                                                  ▼
[유저 단: 반수동 디자인 편집] <──(API: 데이터 수신)──┘
 - Clean Plate 배경 이미지 위에
 - 수정 가능한 텍스트 객체 레이어 결합
① 1단계 : 이미지 업로드 및 텍스트 탐지 (Text Detection)
유저단 (Frontend): 유저가 컴퓨터에 있던 상세페이지 이미지(JPG/PNG)를 캔바 편집 창에 업로드하고 텍스트 추출 버튼을 클릭합니다.
API 통신: 웹 브라우저가 이미지 파일을 바이너리 데이터로 변환하여 서버의 API 엔드포인트로 전송합니다.
서버단 (Backend/Python): 서버가 이미지를 수신하면 파이썬 환경의 PaddleOCR 또는 CRAFT 모델이 가동됩니다. 이미지 안에서 글자가 위치한 픽셀 좌표 바운딩 박스(Bounding Box)를 정확히 찾아냅니다.
② 2단계 : 글자 외곽선 정밀 분리 (Text Segmentation)
서버단 (Backend/Python): 탐지된 글자 좌표를 기반으로 Meta의 SAM (Segment Anything Model)이 작동합니다. 사각형 박스가 아니라 글자의 초성, 중성, 종성 획 하나하나의 외곽선만 따서 정밀한 픽셀 마스크(Mask) 레이어를 생성합니다. 복잡한 배경 이미지와 글자를 물리적으로 격리하는 핵심 단계입니다.
③ 3단계 : 하부 배경 인페인팅 복원 (Generative Inpainting)
서버단 (Backend/Python): 글자 픽셀이 상위 레이어로 분리되면서 원본 이미지 바닥에는 글자 모양의 텅 빈 구멍이 생깁니다. 이때 파이썬 백엔드의 LaMa (Large Mask Inpainting) 또는 SDXL Inpainting 알고리즘이 가동됩니다.
메커니즘: 구멍 주변의 색상 그라데이션, 패턴, 질감 데이터의 연속성을 수학적으로 추론·생성하여 메웁니다. 이를 통해 "글자가 단 한 번도 적힌 적 없었던 완벽하고 깨끗한 원본 배경판(Clean Plate)" 이미지 파일을 완성합니다.
④ 4단계 : 폰트 스타일 모방 및 문자 벡터화 (Style Matching & Vectorization)
서버단 (Backend/Python): 2단계에서 떼어낸 글자 픽셀을 기계가 읽고 수정할 수 있는 실제 텍스트 데이터(String)로 바꿉니다. 동시에 Few-Shot Font Generation 모델이 원본 한국어 글꼴의 굵기, 색상, 기울기 등의 속성을 추출하여 다국어 폰트 라이브러리와 매칭하고, 가변 텍스트 객체(Vector)로 포맷을 변환합니다.
⑤ 5단계 : 편집 레이어 반환 및 유저단 최종 편집 (Frontend Rendering)
API 통신: 서버는 연산을 끝내고 두 가지 데이터를 유저의 브라우저로 다시 쏩니다. [3단계에서 복원한 깨끗한 배경 이미지 파일]과 [4단계에서 추출한 글자 좌표 및 텍스트 정보가 담긴 JSON 데이터]입니다.
유저단 (Frontend): 캔바의 HTML5 Canvas API 엔진이 화면에 깨끗한 배경 이미지를 먼저 깔고, 그 정확한 좌표 위에 마우스로 더블클릭해 지울 수 있는 텍스트 상자를 레이어로 얹어줍니다.
반수동 마무리: 유저는 배경이 깨질 걱정 없이 기존 한국어 글자를 삭제(Delete)하고, 미리 준비한 현지어(영어, 태국어 등) 번역문을 복사·붙여넣기(Ctrl+V) 하여 레이아웃을 마우스로 조절해 최종 상세페이지를 완성합니다.
